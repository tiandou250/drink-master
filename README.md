# 饮料小当家 · Drink Master

市面主流奶茶与咖啡的爆款饮品，拆成家里能做的配方。

有分层图、具体用量、分步做法和避坑提示——**不是官方配方，是家庭条件下的还原版**。

## 内容

覆盖咖啡、奶茶、轻乳茶、果茶、柠檬茶、特调 / 沙冰 / 奶昔六大类，另有小料与基底做法。含不含咖啡因可在页面上一键筛选。

**这里刻意不写具体款数**——配方随时会增加，任何数字写进文档就会过期，页面标题和文案里也不带数量。页面左上角的统计徽标由脚本实时统计 `window.DRINKS` 得出，加一款饮品会自动变。

要看当前实时统计，跑：

```bash
node scripts/check.js
```

它会打印总条目、饮品 / 基底拆分、各品类分布、无咖啡因清单，以及字段与配色校验结果。

## 本地打开

**直接双击 `index.html` 就能用。** 不需要安装任何东西，不需要构建，不需要起服务器。

这是因为数据存成 `.js` 而不是 `.json`——如果用 JSON + `fetch`，双击打开会被浏览器的 CORS 拦掉，页面直接白屏。

## 加一款新饮品

在对应的 `data/*.js` 里追加一条：

```js
{
  id:'wei-yi-biao-shi',        // 唯一，英文或拼音
  name:'饮品名',
  category:'咖啡',              // 咖啡|奶茶|轻乳茶|果茶|柠檬茶|特调|小料
  brands:['品牌A','品牌B'],
  method:'分层',                // 直调|分层|摇匀|打沙|需煮|打泡|浸泡
  difficulty:1,                 // 1-3
  temp:'冰',                    // 冰|热|冷热皆可
  volume:500,
  bg:'#FCD34D',                 // 卡片底色，同品类内别重复
  nocaf:true,                   // 可选：不含咖啡因才写
  layers:[                      // 分层图，pct 之和会自动归一化
    {name:'浓缩咖啡', pct:25, color:'#6F4E37'},
    {name:'厚椰乳', pct:75, color:'#F0DFC8'}
  ],
  intro:'一句话说清这杯的特点或难点。',
  ingredients:[
    {name:'厚椰乳', amount:'200ml', note:'替代方案写这里'},
    {name:'糖浆', amount:'10ml', optional:true}
  ],
  tools:['杯子','勺子'],
  pitfalls:['容易做错的第一点。','第二点。'],
  fidelity:'和店里的差别在哪。',
  steps:[
    {title:'步骤标题', desc:'具体怎么做。', act:'倒入',
     add:[{name:'厚椰乳', pct:36, color:'#F0DFC8'}]},   // add 决定这一步杯子变成什么状态
    {title:'需要等待的步骤', desc:'...', timer:180, act:'加热'}  // timer 单位秒
  ]
}
```

改完跑一下校验：

```bash
node scripts/check.js
```

会检查字段完整性、id 唯一、用量是否写了「适量」、配色在同品类内是否重复。

## 内容规范

这个库的质量靠三条红线撑着，加新配方时请保持：

1. **禁止「适量」「少许」「若干」**——一律换算成 g / ml / 颗。网上配方失败率高，八成死在「适量」两个字上。
2. **一步只讲一个动作**——「倒入椰乳并搅拌均匀」要拆成两步。
3. **需要等待就必须给 timer**——泡茶 3 分钟、摇 15 秒、焖 10 分钟。

另外每条都要有 `fidelity` 说明和店里的差别。**不假装是官方配方。**

## 配色

界面是黑白灰，只有饮品本身有颜色。卡片底色取自 Tailwind 色板，按品类划分色相区段：

| 品类 | 色相 |
|---|---|
| 咖啡 | 琥珀 / 橙 / 黄 |
| 奶茶 | 橙红 / 玫瑰 / 粉 |
| 轻乳茶 | 青 / 蓝绿 |
| 果茶 | 紫 / 粉 / 玫红 |
| 柠檬茶 | 绿 / 黄绿 |
| 特调 | 蓝 / 靛 |
| 小料 | 中性灰 |

**同品类内不重复，跨品类可以重复**——因为用户筛选后看到的是同一品类。

## 技术

纯原生 HTML + CSS + JS。无框架、无依赖、无构建、无后端。

- 分层图由 `layers` 比例实时计算生成 SVG，零图片资源
- 制作页每一步的杯子状态由前面所有步骤的 `add` 累积得出
- 备料勾选状态存在内存中，页面刷新会重置
- 完成页的烟花是 Canvas 方块粒子

## 动效层

`motion.css` + `motion.js` 参考 [fronted-helper](https://tiandou250.github.io/fronted-helper/) 动效库做了筛选移植，覆盖入场转场、交互反馈、组件、滚动、文字、状态、环境氛围七类。

**筛选原则**：只保留结构性动效（位移、缩放、旋转、描边、遮罩、级联、翻转），剔除玻璃拟态、极光、光斑漂移、外发光这类柔光效果——它们和本站「3px 黑框 + 零模糊硬阴影」的粗野主义语言冲突。

**接入方式**：渲染与交互逻辑保持原样，动效层用 `document` 事件委托 + `MutationObserver`（只监听 `childList`，不监听 `attributes`）挂载，因此勾选原料时只改 class、不会触发重新装饰，之前修好的「勾选不重绘」不受影响。

**已移除**：饮品色幕布横扫（切屏时遮挡感太重）、完成页「干杯 CHEERS 饮料小当家」跑马灯横条。

**随机表情**：制作页每步的鼓励 emoji 从 28 个脸部表情池里随机取 1–3 个（同一串不重复），鼓励文案也从分组文案池随机取，不再是固定四句；完成页副标题附一个随机笑脸。动作标签（🧊 铺冰、🔥 加热）和干杯的 🥂 保留功能性 emoji——它们要说明「这一步在干什么」，换成笑脸会丢信息。

**几个实现要点**：

- `MutationObserver` 回调里同步装饰，不用 `requestAnimationFrame` 延迟——后台标签页会节流 rAF，会导致后续重绘漏掉整批动效。
- 数字滚动（`countUp`）带 `setTimeout` 终值兜底，避免 rAF 被节流后数字卡在中间值。
- 滚动区块揭示（`IntersectionObserver`）有 600ms 强制显示兜底，避免内容长时间不可见。
- 无限循环动效控制在 3 个以内且幅度极轻；漂浮动画挂在杯子内部 SVG 上，不占用容器的 `transform`，否则会盖掉 hover 抬升。
- 全部遵守 `prefers-reduced-motion` 与 `(hover:none)` 兜底；触屏设备禁用磁吸、光标跟随与漂浮。

## 功能模块

`features.css` + `features.js` 提供两个入口，位于左栏搜索框下方：

- **抽一杯**：从全部饮品里纯随机抽一款，**不做任何条件过滤**。弹窗里有「换一杯」（会排除上一次抽到的那杯）和「就做这杯」（直接进备料页）。
- **手边有什么**：勾选手头原料，反查「现在就能做」和「只差一样」的饮品，后者在卡片上标出缺哪一味。

数据层面有三个前提，缺一个功能就会「看着能用其实漏一半」：

1. **原料别名归一**：数据里「牛奶 / 鲜奶 / 全脂牛奶 / 鲜牛乳 / 冰博克牛奶」是五种写法，`features.js` 归并到「牛奶」；「厚椰乳 / 椰浆」归并到「椰乳」。茶底与风味糖浆不归并，避免把不同风味硬凑成一样。
2. **常备料排除**：糖、水、冰、盐等几乎每杯都有，已从词表和匹配中剔除，否则「只差一样」永远差的是冰块。
3. **零结果引导**：只勾一两样时「现在就能做」必然为空（多数饮品都需要第二样核心料），此时列出「补上一样就有得喝」建议，按能解锁的款数排序，点一下直接勾上。

模块独立于 `app.js`：通过全局作用域复用 `state` / `renderCards` / `renderDetail` / `stopTimer` / `cupSVG`，不修改主逻辑；样式也自包含，不依赖 `motion.css`。
